# Architecture

## Monorepo Structure

```
design-system/
├── apps/
│   ├── docs/          # Documentation site
│   └── storybook/     # Component documentation
├── packages/          # Component packages (@uiid/*)
│   ├── buttons/, cards/, forms/, layout/, typography/, ...
│   ├── config/        # @uiid/config: shared build, test and typecheck config, CI checks (internal)
│   └── tokens/        # Design tokens (JSON → CSS, generated by build-tokens.js)
└── .claude/           # Agent rules (rules/) and settings.json, which installs the uiid plugin
```

## Root Config Files

| File             | Purpose                                                                                                   |
| ---------------- | --------------------------------------------------------------------------------------------------------- |
| `tsconfig.json`  | Base TypeScript config                                                                                    |
| `turbo.json`     | Turbo task orchestration                                                                                  |
| `.size-limit.js` | Size entries, generated from `packages/*`                                                                 |
| `.oxlintrc.json` | oxlint configuration (whole repo)                                                                         |
| `.oxfmtrc.json`  | oxfmt formatter configuration                                                                             |
| `lefthook.yml`   | Git hooks (pre-commit format+lint, commit-msg)                                                            |
| `.nvmrc`         | The one declared Node major, read by nvm/fnm and every `actions/setup-node` step; Vercel does not read it |

## Shared Config Package

`packages/config` is `@uiid/config`: private, never built or published, and skipped by the registration, dist and size checks. Every package lists it as a `workspace:*` devDependency. Its Vite config is imported by package name (`@uiid/config/vite`); tsconfigs and `node` commands reach it by relative path (`../config/...`), since neither can resolve a package name. Root scripts pass `--config` or `-p` to the Vitest and typecheck files, so `pnpm test`, `pnpm test:browser` and `pnpm typecheck` run from the root as before.

| File                          | Purpose                                                                                                    |
| ----------------------------- | ---------------------------------------------------------------------------------------------------------- |
| `vite.config.ts`              | Shared Vite build config factory, `createViteConfig`                                                       |
| `scripts/`                    | Build helpers (CSS layers and target, dts rewrite), the CI checks, `postinstall` and test helpers          |
| `tsconfig.package.json`       | Package build config every `packages/*/tsconfig.json` extends: declaration-only emit to `dist`, no tests   |
| `tsconfig.check.json`         | Build-free `pnpm typecheck` of packages and Storybook; `apps/docs/tsconfig.check.json` covers the docs app |
| `tsconfig.check.browser.json` | Typecheck of the real-browser tests, kept apart because `vitest/browser` retypes jest-dom's matchers       |
| `vitest.config.ts`            | Test configuration for all packages, rooted at the repo root                                               |
| `vitest.browser.config.ts`    | Real-browser tests (`*.browser.test.tsx`), run by `pnpm test:browser`                                      |
| `vitest.setup.ts`             | Test setup (jest-dom matchers)                                                                             |
| `vitest.globalSetup.ts`       | Generates token CSS and per-icon modules, so tests need no build; Storybook's `main.ts` does the same      |
